# Google Wallet 実装の全体像

パスを1枚出すまでの流れ。詳細なコードやコンソール操作は後続ドキュメント用。ここでは全体像だけ置く。

公式の手順まとめ:
[Google Wallet pass development flow](https://developers.google.com/wallet/generic/overview/add-to-google-wallet-flow)

## 事前準備

1. [Google Pay & Wallet Console](https://pay.google.com/business/console) でIssuerアカウントを作る
2. 最初はデモモード。許可したテストユーザーだけが保存できる
3. Google Cloudプロジェクトで Google Wallet API を有効化
4. サービスアカウントを作り、JSON鍵を発行する
5. そのサービスアカウントのメールをIssuerに Developer として招待する
6. 本番公開はコンソールから審査（publishing access）を取る

Androidアプリから出す場合は、Play services とアプリ署名証明書のSHA-1もコンソールに登録する。

認証の公式手順:
[Generating Google Wallet REST API authentication credentials](https://developers.google.com/wallet/retail/offers/getting-started/auth/rest)

## パスの作り方

ほぼすべての券面は Class + Object。

- Class: 共通テンプレート。コンソールでもRESTでも作れる
- Object: 1ユーザー1枚。RESTまたはAndroid SDKで作る

IDの形はどちらも `ISSUER_ID.任意のサフィックス`。

例（イベントチケットのObjectのイメージ）:

```json
{
  "id": "ISSUER_ID.OBJECT_ID",
  "classId": "ISSUER_ID.EVENT_CLASS_ID",
  "state": "ACTIVE",
  "barcode": {
    "type": "QR_CODE",
    "value": "BARCODE_VALUE"
  }
}
```

作り方は2通り。

- **先にAPIで作る**: Class / Object を `POST` しておき、保存リンクのJWTにはIDだけ入れる。保存される数が多そうなときに向く
- **JWTにJSONを埋め込む（just-in-time）**: ユーザーが「追加」したタイミングでGoogle側に作られる。作って使われないオブジェクトを減らせる

Genericの作成手順:
[Create Passes Classes and Passes Objects](https://developers.google.com/wallet/generic/use-cases/create)

RESTのベースURL:

```text
https://walletobjects.googleapis.com/walletobjects/v1/
```

例: Generic class の作成は `POST /walletobjects/v1/genericClass`。

## ユーザーに渡す（JWT）

ユーザーが保存できる状態にするには、Class / Object をJWTに載せて署名する。

JWTの主なクレーム:

| フィールド | 値 |
| --- | --- |
| `iss` | サービスアカウントのメール |
| `aud` | `google` |
| `typ` | `savetowallet` |
| `iat` | UNIX秒 |
| `origins` | 保存ボタンを出すドメイン（Webでは必須に近い） |
| `payload` | 対象の class / object |

署名はサービスアカウントの秘密鍵で RS256。秘密鍵はサーバー側だけ。クライアントに出さない。

Web / メール / SMS ではこのURLにする:

```text
https://pay.google.com/gp/v/save/<signed_jwt>
```

可能なら公式の「Google ウォレットに追加」ボタン画像を使う。  
[ブランドガイドライン](https://developers.google.com/wallet/generic/resources/brand-guidelines)

Androidアプリでは Wallet Android SDK の `savePasses` / `savePassesJwt` を使う。SDK経路ではアプリ署名のSHA-1でJWT署名を肩代わりできる。

JWTの公式:
[Working with JSON Web Tokens](https://developers.google.com/wallet/generic/use-cases/jwt)

Codelab:
[Create passes on Web](https://codelabs.developers.google.com/add-to-wallet-web)

## 更新

保存後の変更はGoogleのAPIを叩く。端末向けの更新サーバーは持たない（Appleとの最大差のひとつ）。

- Class を直す → そのテンプレートを使っているパス全体
- Object を直す → その1枚だけ
- 全体上書き: `PUT`（送っていないフィールドは消えるので、先に `GET` した方が安全）
- 一部だけ: `PATCH`

例:

```text
PATCH https://walletobjects.googleapis.com/walletobjects/v1/eventticketobject/{resourceId}
```

[Update Passes Classes and Passes Objects](https://developers.google.com/wallet/retail/gift-cards/use-cases/updates)

できないこと・制限:

- Class / Object の削除APIはない。ユーザーがウォレットから外すことはできる
- 開発者独自のプッシュ通知は出せない
- レートリミットはおおむね 20リクエスト/秒
- タイムアウト目安は10秒（公式FAQ）

組み込み通知の例（FAQより）:

| タイプ | 内容 | タイミング |
| --- | --- | --- |
| Event | 開催前リマインド | 3時間前 |
| Boarding pass | 出発前リマインド | 3時間前 |
| Boarding pass | 更新通知 | ゲート・出発時刻などの変更 |
| Offer | 期限リマインド | 48時間前 |
| Generic | 開始前 / 期限 | 24時間前 / 48時間前 |

## 配布チャネル

| チャネル | やり方 |
| --- | --- |
| Web | 保存リンク or 公式ボタン。`origins` を合わせる |
| メール / SMS | 同じ保存リンク |
| Androidアプリ | Android SDK |
| QR | 保存用ページやリンクをQRにする（`.pkpass` ではない） |

JWTが長すぎてURL制限（目安1800文字）に当たったら、Class / Object を先にAPI作成してJWTを短くする。

## Apple実装との対比（最短）

同じ機能を両方出すときの分岐。

| 工程 | Apple | Google |
| --- | --- | --- |
| テンプレ | `pass.json` のスタイル | Passes Class |
| 1枚 | `.pkpass` に含める | Passes Object |
| 配布 | ファイルダウンロード | JWTリンク / SDK |
| 更新 | 自前Webサービス + APNs | Wallet API の PATCH/PUT |
| NFC | Apple VAS + entitlement | Smart Tap |

詳細は [iOS Walletとの比較](./iOS%20Walletとの比較.md)。
